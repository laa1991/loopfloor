## 0. 本仓放什么 / 不放什么

**放**：能复现结论的东西（测量方法、框架、协议），以及抄了不伤人的通用基建。

**不放**（逐条，各附一句理由）：

- **调度与规划轮** —— 那是跑在我们自己运行时里的决策层，脱离它的上下文就只剩一段看不出对错的流程；
- **记忆层 / 记忆库** —— 里面是我们的私有语料；
- **内部判据集** —— 判据的**形状**可以放（见 §3、§4），我们**自己那份**不放；
- **人格核心、提示词与知识注入** —— 有很多可以深入的地方，**欢迎私下交流**；
- **压缩等机制的具体实现** —— 本仓讲的是这几格的**归宿与判据**，不是某一份实现的代码；
- **任何部署路径、凭据、个人身份线索** —— 零例外。

> 这条边界是护栏：写给读的人，也写给以后的我们。

## 1. 四处坏法

长程任务（跨多个上下文窗口、多轮压缩、可能跨进程换代的活）会以四种方式坏掉。它们的共同点是**静默**——不抛异常、不进重试、不留告警，只是让结果慢慢变成另一个东西。

| 症状 | 形状 | 你怎么发现它 |
|---|---|---|
| **上下文爆** | 历史把窗口吃满；越到后面越贵、越钝 | 有读数（占比），但多数人不知道算哪一段 |
| **丢状态** | 换窗口 / 压缩 / 换代之后，「上次到哪了」没人知道 | 通常表现为从零开始，或照着旧步子继续 |
| **偏目标** | 做得好好的，做的事已经不是原来那件事 | 「为什么做这件事」只能从对话历史里翻 |
| **假完成** | 宣称完成了，但**没有一条证据是系统自己产生的** | 「✓ 通过」来自做这件事的同一个主体 |

这四处都不报错，所以**没有一条判据会自己响**。这份材料做的就是给每一处配一个「能响的东西」。

## 2. 与相邻工作的关系

我们只引公开材料，并**逐字标注出处**（行号指公开仓 README 的当次快照）。

**有一篇 survey 已经给这一层命了名**（RUC-NLPIR / `Awesome-Long-Horizon-Agents`，News 记 2026/07）：

> Long-horizon agency is a system-level capability jointly shaped by external harness engineering and internal model optimization.
> （Externalized Harness Engineering 一栏，逐字：`Loops and workflows · Context and memory · Tools and skills · Orchestration · Hooks · Verification`）

**有一类做法用「加角色」解**（AMAP-ML / `LongHorizon-Harness`）：

> `### One loop. Three focused responsibilities.`
> Manager：`Rebuilds each round from the original goal, verified progress, failure evidence, and remaining work`
> Auditor：`Independently inspects the actual files, interfaces, logs, and tests instead of trusting the Executor's claim`

**它的验收方式是值得学的**：`### Same model. Same execution backend. Only the harness changes.`——把 harness 当唯一的自变量，再用**外部评分器**量差别。

**我们用「加结构」解**：状态**外置**成盘上的东西（机制 / 载体 / 装置），每格有写入口、有读入口、有判据。差别不在省钱，在两处：

1. **状态的家数**：角色各自会长出一份任务理解（多份可能分歧的状态），于是不得不**再用一个新角色**去兜这个分裂；
2. **可复现性**：结构是**数据**（能 diff、能重放、能复算），角色是**行为**（同一角色两次跑出来是两条不同轨迹）。

> ✅ **前半句有可跑的判据**（2026-09-25 **加固**）：`demo/` 零依赖，`node demo/check.mjs`，exit code 就是判决。**七条判据里两条是负对照**——因为「同日志重放两次相同」这种检查**天生不会失败**（任何确定性函数都过），所以它旁边必须站一条**能失败**的判据：折法不得读日志之外的东西（时钟 / 随机 / 环境变量 / 网络），且同一把扫描**在被污染过的副本上必须触发**。判据 4 也从「检查一个字符串」改成「**引用的那条记录必须真实存在、且不是收口自身**」，配一份引用空气的日志当负对照。每条**不证明什么**写在 `demo/README.md` 里。
> ⚠️ **后半句仍只是论证**：「角色是行为、不可复现」本演示**不证**——演示里没有模型，用一个确定性的替身去假装证明它，等于拿自己造的官当裁判。要做那半，得另有一套实物。

### 2.1 空档在哪

上面那六节（`Loops and workflows` / `Context and memory` / `Tools and skills` / `Orchestration` / `Hooks` / `Verification`）是**类目名，不是内容清单**——我们**没有**做过「这六类覆盖的全部材料里有没有这一格」的检索（那是另一个工作量级）。我们能说的是：

> **任务态怎么活过窗口切换、压缩、进程换代。**

它被默认塞进「循环」或「上下文」里，而这两节都不是为它设计的。**这一格就是本仓要占的位置。**（**若你见过把它单列成一节的公开材料，请指给我们**——那正是我们想对上的坐标。注意「有材料提到 / 覆盖它」与「把它**作为一节来设计**」是两件事，我们说的空档是后者。）

### 2.2 与「自带压缩 + 笔记库 + skill/AGENT.md + 钩子 + CI」这套现成组合的分界（有人问过）

**问题逐字**：*「这和他用 harness 自带的 compaction，加一个 obsidian vault 写 markdown，主要的区别是啥。以及创新点是什么：harness+obsidian+skill+agent.md+pre-commit hook+github action 不能解决的，才是创新点。」*

**先把对方那套覆盖了什么摆清**（不摆清，讨论就变成自说自话）：

| 那套件 | 它管的那一格 | 我们的位置 |
|---|---|---|
| Obsidian vault 写 markdown | **盘上的知识**（人可读 / 可链 / 可版本控制） | 我们的「机制」也落在盘上 ⇒ **这一格我们不占优势** |
| skill / AGENT.md | **指令的注入**（把约定放进模型眼前） | 同族。我们多问一句：**这条注入在切换点上还在不在** |
| harness 自带的 compaction | **上下文有多长** | 它管长度，**不管「丢完之后还剩什么」** ⇒ **切换点就在这** |
| pre-commit hook / GitHub Action | **提交边界上的门** | 那道门只在**提交那一刻**看得见；下面四个坏法都发生在**提交之间**的循环里 |

**分界点（一句）**：

> 那套机制管的是**「盘上存了什么」**与**「提交时拦不拦」**；本仓管的是**「模型此刻眼前有什么」**与**「切换点上有没有一条会自己响的判据」**。

**三个可测的差别**（每条都能在**别人的**设置上跑，不需要我们这套实现）：

1. **在场 ≠ 存在**：vault 里那篇笔记**不会自己走到眼前**。
   判据：**换窗口后的第一轮输入里，有没有一条说得出 ①上次做到哪 ②在等什么 ③为什么**——问的是「在场」，不是「盘上有没有那篇笔记」。
2. **压缩之后谁负责回来**：压缩恰好是**让卡片消失**的那个动作；vault 不受影响，**但也不会补位**。
   判据：**压缩前后，任务态那一块是「自己回来」还是「要人记得去读」**。
3. **门的位置**：hook / CI 在**提交边界**触发；本仓要的判据落在**循环内**。
   判据：**你那道门能不能拦住一个「还没提交」的错误方向**（计划漂了、状态丢了、完成了假的）。

**创新点——我们只认一条**：

> **不是「用了什么机制」，而是「给每一格配一条会在切换点上自己响、且自带负对照的判据」。**
> 判据要**可移植**（喂一份日志就能跑）、**零模型**（自带两侧对照，指不出哪个输入能让它失败就不算判据），
> 因此**你可以拿它去量你自己那套栈**——那才是它跟「又一层笔记/又一份约定」的区别。

**两根轴，是对方替我们点出来的**（也写下来，免得这一节里只有我们那一半）：

1. **任务的可重复性决定状态有多贵**。流程固定时（写代码那条 `grill → spec → ticket → 实现 → 评审`，
   有人跑过几百上千趟），状态外置**几乎免费**——每个阶段的产物本身就是状态；流程不固定时（探索、判断、跨线），
   状态会**贵到会丢**。⇒ 本仓那四种坏法是为**「不固定」那一半**写的；而一条固定流水线恰好是
   **「固定」那一半的自证**，不是反例。
   ⇒ 自测一句：**你的流程固定吗？** 固定的话，本仓大半对你没有用——这不是谦虚，是这一节能给出的最有用的判断。
2. **每轮重钉与按需检索是两半，不是对手**。每轮重钉（卡片、指针）解的是**切换之后的第一轮**——
   那一刻还没人来搜；按需检索（搜索、召回）解的是「记不住但找得回」。
   真正的分界是：**切换之后的第一轮，由谁负责。**

**我们不敢说的一句**（写出来免得它变成暗示）：如果他确实用 hook / skill 把「下一步」**每一轮重新注入**，
那这套栈**能覆盖前两格的一部分**——差别就缩到「**压缩之后谁重钉**」和「**有没有判据**」。
所以这条分界**欢迎反例**：拿你的设置在 §3 那一列问句上跑一遍，把结果贴回来，比我们在这里论证有用。

## 3. 四格 × 归宿 × 形态

| 症状 | 归宿（机制） | 形态 | 判据（一句可测的问句） |
|---|---|---|---|
| 上下文爆 | 压缩 + 注入面按**变更频率**分层 + 大输出落盘 | **机制** | 这条会话里历史占多少？压的时候丢了什么，有没有记账？ |
| 丢状态 | 接续指针（写在盘上）+ 任务态外置的常驻面 | **机制** | 换窗口后，**第一轮的输入里有没有「上次到哪了」**？ |
| 偏目标 | 会话目标 / 阶段进度 / 跨会话软目标 三层载体 + 收口时回望 | **载体 + 一个动作** | 「我为什么做这件事」来自对话历史，还是来自目标本身？ |
| 假完成 | 仪表 + 账本 | **装置** | 这次「完成」里，**哪一条证据不是这个系统自己产生的**？ |

**形态三样：机制 / 载体 / 装置**，三样都是盘上的东西。这是「零角色」的准确版本：不是「我们不用角色」，而是**这四格各自都有非角色的归宿**。

**最简实现公式（三件）** —— 四格说的是**会怎么坏**；这一段说的是**最少要有什么**：

> **长程任务 = 一个写在盘上的「下一步」 + 一个每轮重新出现的「现在在哪」 + 一个敢丢历史的「压缩」。**

| # | 件 | 负责什么 | 替哪一格兜底 | 去掉它会怎样 |
|---|---|---|---|---|
| ① | **接续指针** | 把「下一步」写在盘上——单数、覆盖式、带来源 | 丢状态 | 换窗口 / 换代后：要么从零重来，要么照着一份**已经过期**的计划继续 |
| ② | **工作台** | 把**任务态**搬到**每轮都会重新出现**的那个面 | 丢状态 + 偏目标 | 状态还在日志里，**但不在视野里** ⇒ 下一步由最近看到的几句话决定 |
| ③ | **压缩** | 让历史**有上限**——丢得起的丢掉，并**记账** | 上下文爆 | 走不过第一次爆窗；「长程」只剩「一次超长会话」 |

**缺任何一件都不是「少一点」**：没有 ③，你到不了需要接续的那一刻；只有 ①，方向会被历史带偏；只有 ②，换一个窗口就断了。

**为什么是这三件、它们怎么咬合**（尤其 ③ 与 ②：**③ 负责「丢得起」，①② 负责「丢完之后还剩什么」**）⇒ `docs/06-最简实现公式.md`。

⚠️ **范围与分解也是口径的一部分**：同一批名字换一组根集，读数就从 `17/1` 变成 `16/2`；同一段材料换一种分解，计数型那个量会**翻号**。所以——**报「找不到 / 不可还原」必须连范围一起报**，**分解对不齐的两段不许比方向（拒答）**。细则与判据见 `docs/05-尺自己也会安静地错.md` §3。

⚠️ **两条边界，必须和这张表一起读**：① **语料在动**——同一口径相隔 5 分钟的两次跑是 707 与 708 个会话、1035 与 1037 次写，所以**每个数都要带 as-of**，**相邻两次跑的数不能混用**（本表全部来自同一次跑；本文件此前正是栽在这一条上）。② **这些数随仓不可复算**——它们来自**某一个部署的会话日志**，随仓那两份样本只用来验计数规则。**方法可复现，数字不可复现**，这是这份材料的一处真实边界，不藏。

**关于「零出现」**：我们一度把某一行状态「在注入里从未出现」当成一个结论。实测下来它有**四个世界**，而日志里它们**同形**：① 该块**已被删**（刻意的设计决定）；② **曾经永远打不出来**（投影作用域与注入时机的顺序问题）；③ 条件式渲染 + **分母太小**（多数会话本就没有那一项）；④ **整块被实验性关闭**（配置层开关）。

> ⇒ **一般形状**：「零出现」不是证据。要判它，得先能分开这四个世界——我们的做法是**预注册 + 每次变更当场记一行带真身判据**，而不是事后从日志里推。

## 5. 我们最弱的一格（连终点一起摆出来）

**第四格「假完成」目前只有设计，没有仪表。**

我们没有把它写成「正在收集数据」——那句话没有出口条件，会变成永久状态。我们把它写成**可判定的终点**：

- **出口 ①（账本）**：账本里每一条都能回答「**它下一次会在什么信号上自己冒出来**」——观察者（谁 @ 什么时刻能看见它）· 还原（至少一个位置，达标是指针）· 实测（开过火没，没开过写 `未验`）。
- **出口 ②（仪表）**：仪表能答一句**今天答不出**的话，例如「最近 7 天，判据触发几次、误报几次」。答得出 = 数据收完；答不出 = 还没到。

**为什么先做这一格**：① 唯一已经写出出口条件的；② 唯一命中过真实事故的；③ 判据仍是问句的三格里，只有它能立刻变成装置。

> **把最弱的一格连它的终点一起摆出来，比藏起来更像一份测量。**

## 6. 边界（明写不做的事）

- **给测量，不给我们的实现**：口径、判据、失败样本公开；依赖某个具体部署才能跑的实现留在本地。每条读数标注了它能否脱离那个部署复现。
- **不承诺 benchmark**：我们没有跨 harness 的同模型对照实验，就不写「比谁好」。要写，必须是**同模型 + 同执行后端 + 只换 harness**，并附第三方能跑的评分器；没做到就写没做到。
- **不写没有口径的数**：任何数字后面要么跟复现方式，要么标「未量」。
- **失败样本与结论同等对待**：能证明我们错的样本进正文，不进附录。
- **不出现任何未公开的部署细节**：路径、凭据、会话标识一律不写。
- **「看得见」是我们选的下沿，不是我们没走到那儿**：`docs/05` §5 的盲区（只量「偏了**看得见吗**」、不量「偏了**有没有造成损失**」）与 `docs/06` §5 的「**不承诺做得对**」（三件齐了照样可以把事做错）**是同一条线的两端**。这条线是**划的界**：本仓量的是「状态在不在、看不看得见」，不是「决策对不对、损失多大」——后者要另一套实物（同模型 + 同执行后端 + 只换 harness，外加第三方能跑的评分器，见上一条）。**请不要把它读成「这两件事他们想做、但没做到」。**

## 7. 怎么读这份材料 / 出处
