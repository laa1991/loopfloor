## 0. 本仓放什么 / 不放什么

**放**：能复现结论的东西（尺、框架、协议），以及抄了不伤人的通用基建。

**不放**（逐条，各附一句理由）：

- **调度与规划轮** —— 那是跑在我们自己运行时里的决策层，脱离它的上下文就只剩一段看不出对错的流程；
- **落差 → 判据 → 蒸馏** 这条链 —— 它绑着我们的内部读数口径，放出去会变成「看起来能复现、实际复现不了」；
- **记忆层 / 记忆库** —— 里面是我们的私有语料；
- **内部判据集** —— 判据的**形状**可以放（见 §3、§4），我们**自己那份**不放；
- **人格核心、提示词与知识注入** —— 与工程主题无关，且属于个人；
- **压缩等机制的具体实现** —— 本仓讲的是这几格的**归宿与判据**，不是某一份实现的代码；
- **任何部署路径、凭据、个人身份线索** —— 零例外。

> 这条边界是护栏：写给读的人，也写给以后的我们。

## 1. 四处坏法

长程任务（跨多个上下文窗口、多轮压缩、可能跨进程换代的活）会以四种方式坏掉。它们的共同点是**静默**——不抛异常、不进重试、不留告警，只是让结果慢慢变成另一个东西。

| 症状 | 形状 | 你怎么发现它 |
|---|---|---|
| **上下文爆** | 历史把窗口吃满；越到后面越贵、越钝 | 有读数（占比），但多数人不知道算哪一段 |
| **丢状态** | 换窗口 / 压缩 / 换代之后，「上次到哪了」没人知道 | 通常表现为从零开始，或照着旧步子继续 |
| **偏目标** | 做得好好的，做的事已经不是原来那件事 | 「为什么做这件事」只能从对话历史里翻 |
| **假完成** | 宣称完成了，但**没有一条证据是系统自己产生的** | 「✓ 通过」来自做这件事的同一个主体 |

这四处都不报错，所以**没有一条判据会自己响**。这份材料做的就是给每一处配一个「能响的东西」。

## 2. 与相邻工作的关系

我们只引公开材料，并**逐字标注出处**（行号指公开仓 README 的当次快照）。

**有一篇 survey 已经给这一层命了名**（RUC-NLPIR / `Awesome-Long-Horizon-Agents`，News 记 2026/07）：

> Long-horizon agency is a system-level capability jointly shaped by external harness engineering and internal model optimization.
> （Externalized Harness Engineering 一栏，逐字：`Loops and workflows · Context and memory · Tools and skills · Orchestration · Hooks · Verification`）

**有一类做法用「加角色」解**（AMAP-ML / `LongHorizon-Harness`）：

> `### One loop. Three focused responsibilities.`
> Manager：`Rebuilds each round from the original goal, verified progress, failure evidence, and remaining work`
> Auditor：`Independently inspects the actual files, interfaces, logs, and tests instead of trusting the Executor's claim`

**它的验收方式是值得学的**：`### Same model. Same execution backend. Only the harness changes.`——把 harness 当唯一的自变量，再用**外部评分器**量差别。

**我们用「加结构」解**：状态**外置**成盘上的东西（件 / 载体 / 装置），每格有写入口、有读入口、有判据。差别不在省钱，在两处：

1. **状态的家数**：角色各自会长出一份任务理解（多份可能分歧的状态），于是不得不**再用一个新角色**去兜这个分裂；
2. **可复现性**：结构是**数据**（能 diff、能重放、能复算），角色是**行为**（同一角色两次跑出来是两条不同轨迹）。

> ✅ **前半句已有可跑的证据**（2026-09-25）：`demo/` 里有一份零依赖的可回放演示——同一份只追加日志折出来的状态**两次逐字相同**（判据 1），世界可倒回（判据 2/3），且目标终结时**点名了外部物**（判据 4）。`node check.mjs`，exit code 就是判决。
> ⚠️ **后半句仍只是论证**：「角色是行为、不可复现」本演示**不证**——演示里没有模型，用一个确定性的替身去假装证明它，等于拿自己造的官当裁判。要做那半，得另有一套实物。

### 2.1 空档在哪

上面那六节（`Loops and workflows` / `Context and memory` / `Tools and skills` / `Orchestration` / `Hooks` / `Verification`）里，**没有一节**是：

> **任务态怎么活过窗口切换、压缩、进程换代。**

它被默认塞进「循环」或「上下文」里，而这两节都不是为它设计的。**这一格就是本仓要占的位置。**

## 3. 四格 × 归宿 × 形态

| 症状 | 归宿（机制） | 形态 | 判据（一句可测的问句） |
|---|---|---|---|
| 上下文爆 | 压缩 + 注入面按**变更频率**分层 + 大输出落盘 | **件** | 这条会话里历史占多少？压的时候丢了什么，有没有记账？ |
| 丢状态 | 接续指针（写在盘上）+ 任务态外置的常驻面 | **件** | 换窗口后，**第一轮的输入里有没有「上次到哪了」**？ |
| 偏目标 | 会话目标 / 阶段进度 / 跨会话软目标 三层载体 + 收口时回望 | **载体 + 一个动作** | 「我为什么做这件事」来自对话历史，还是来自目标本身？ |
| 假完成 | 仪表 + 账本 | **装置** | 这次「完成」里，**哪一条证据不是这个系统自己产生的**？ |

**形态三样：件 / 载体 / 装置**，三样都是盘上的东西。这是「零角色」的准确版本：不是「我们不用角色」，而是**这四格各自都有非角色的归宿**。

## 4. 读数（每条带口径、复现方式与盲区）

**格式约定**：数 = 值（样本 / 口径 / 盲区 / 怎么复现）。**没有口径的数不写。**

| 读数 | 值 | 口径 · 盲区 |
|---|---|---|
| 注入面分区（单会话一帧） | system **5.8%** · tools **2.0%** · messages **92.2%** | 口径：导出**模型可见**的完整 prompt，按区标记行的**位置**切三段。盲区：**区级**可信，**角色级**（历史里各类消息各占多少）口径未成立——导出文本没有格式契约，标记与正文共用一个文本空间，取数会猜错而**不报错** |
| 接续指针写密度 | ≈ **1020** 次 / 45–46 个会话 | 口径：全库会话日志里 `tool/call` 的名称计数（样本 678 个会话）。盲区：**只覆盖工具类**；注入型、UI 型、服务型面看不见 |
| 目标层写密度 | ≈ **0.12** 次/会话（对照：接续指针 ≈1.28） | 同上。⇒ **机制在，用得少**；原因之一是把入口写成了「并列的第二条路」，而并列的第二个选项会变成事实上的默认 |
| 「零出现」的四种成因 | 见下 | 无数字——这是一条**机制发现**，它的价值在判据 |

**关于「零出现」**：我们一度把某一行状态「在注入里从未出现」当成一个结论。实测下来它有**四个世界**，而日志里它们**同形**：① 该块**已被删**（刻意的设计决定）；② **曾经永远打不出来**（投影作用域与注入时机的顺序问题）；③ 条件式渲染 + **分母太小**（多数会话本就没有那一项）；④ **整块被实验性关闭**（配置层开关）。

> ⇒ **一般形状**：「零出现」不是证据。要判它，得先能分开这四个世界——我们的做法是**预注册 + 每次变更当场记一行带真身判据**，而不是事后从日志里推。

## 5. 我们最弱的一格（连终点一起摆出来）

**第四格「假完成」目前只有设计，没有仪表。**

我们没有把它写成「正在收集数据」——那句话没有出口条件，会变成永久状态。我们把它写成**可判定的终点**：

- **出口 ①（账本）**：账本里每一条都能回答「**它下一次会在什么信号上自己冒出来**」——观察者（谁 @ 什么时刻能看见它）· 还原（至少一个位置，达标是指针）· 实测（开过火没，没开过写 `未验`）。
- **出口 ②（仪表）**：仪表能答一句**今天答不出**的话，例如「最近 7 天，判据开火几次、误报几次」。答得出 = 数据收完；答不出 = 还没到。

**为什么先做这一格**：① 唯一已经写出出口条件的；② 唯一命中过真实事故的；③ 判据仍是问句的三格里，只有它能立刻变成装置。

> **把最弱的一格连它的终点一起摆出来，比藏起来更像尺。**

## 6. 边界（明写不做的事）

- **放尺，不放我们的实现**：口径、判据、失败样本公开；依赖某个具体部署才能跑的实现留在本地。每条读数标注了它能否脱离那个部署复现。
- **不承诺 benchmark**：我们没有跨 harness 的同模型对照实验，就不写「比谁好」。要写，必须是**同模型 + 同执行后端 + 只换 harness**，并附第三方能跑的评分器；没做到就写没做到。
- **不写没有口径的数**：任何数字后面要么跟复现方式，要么标「未量」。
- **失败样本与结论同等对待**：能证明我们错的样本进正文，不进附录。
- **不出现任何未公开的部署细节**：路径、凭据、会话标识一律不写。
