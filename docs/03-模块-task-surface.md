# 工作台 / 任务态外置（task-surface）

> 本模块是 `loopfloor` 主题的一节，按仓骨架的五节模板写：解决什么问题 / 形状 · 协议 / 不在本模块 / 依赖 · 前置 / 状态。

## 1. 解决什么问题

**一句话**：把任务态从**对话历史**里搬出来，放到盘上——历史会被压缩、会被换掉，而任务态需要一个不随它消失的家。

**失败场景**：一次上下文压缩之后，目标、计划、已定的事**都还在日志里，但不在视野里**。于是「下一步做什么」不再由任务态决定，而由**最近看到的几句话**决定。它不报错：会话照常继续，模型照常产出，只是方向慢慢偏掉。

## 2. 形状 · 协议

七条约定：

1. **任务态外置**：目标 / 进度 / 已定的事 / 证据 / 下一步，各自有**盘上的家**，与对话历史分离。
2. **唯一第一站**：读「这条线现在是什么状态」只有一个入口、一个答案——不是散在若干处让读者自己拼。**两个家写同一件事，两处必然互相腐烂。**
3. **两层**：**常驻层**（每轮自动出现在视野里的那几行）+ **按需层**（要细节时才去取）。常驻层不是摘要，是**索引**。
4. **常驻层要薄，而且要有理由薄**：它在请求的最前面出现，每多一行就是每轮都要付的钱，且它在链首 ⇒ **在那里改一个字节，代价是其后全部历史**。所以常驻层只放「不读它就会做错」的东西。
5. **投影的形状**：台面是**折出来的**，不是手写的。同一份记录可以喂给多个读者（每轮那一行、面板、按需读入口），它们**同源**——否则同一件事会在两个面上各说各的。
6. **每块要有离场规则**：都要能回答「它什么时候该消失」（任务结束 / 被覆盖 / 过期）。没有离场规则的块会永久占位，而永久占位的东西最后会被所有人忽略。
7. **写入口与读入口各点名一个**：一块状态要么有明确的写入动作，要么有明确的读取动作；两样都没有的块，是个没人填的空槽。

**自查判据（读者用）**：**没有这一块，我会做错哪件事？** 答得出 = 它有承重；答不出 = 它只是好看。

## 3. 不在本模块

- **schema 实例与投影规则**：字段名、事件名、折叠规则**不在本仓**（它们是实现，不是形状）。
- 注入实现、面板 UI、存储格式不在。
- 阈值（多大算大、多久算过期）不在。
- **判据集不在**（与 `pointer` 同一条留白）：本模块给的是「任务态该长成什么形状」，不是「怎么判断这一步真成了」。

## 4. 依赖 · 前置

- **一个只追加的历史**：投影从它折出来。没有历史，任务态就退化成「手写的一块状态」，读者无法判断它从哪来、什么时候写的。
- **一个注入点**：每轮开始前能露面。**注入型比调用型可靠**——调用型要靠「记得去读」，而「记得」本身就是失败模式。
- **一个按需读入口**：常驻层放不下的细节要有地方取。
- **成本的自觉**：常驻层的位置决定了它的代价不成比例——它薄，整个系统就便宜；它厚，每一轮都贵，而且会在压缩后变得更贵。

## 5. 状态

- **协议描述**：本文件（骨架）。
- **实现**：我们这边有一份在跑的，形状与 §2 的七条一致；**本批不搬实现代码**。
- **已知反例**（进正文，不进附录）：
  1. 把一块状态做成**纯调用型**——它会被读得极少，「记得去调它」不是机制；
  2. 常驻层写成**摘要**——越长越贵，而且每轮都在变 ⇒ 每轮断一次请求前缀；
  3. **块被定义了但没人填**——从外面看，空槽与「还没开始」长得一模一样；
  4. **两个读者各读各的源**——同一个台面在两处显示不同内容，且没有任何东西会报错。
