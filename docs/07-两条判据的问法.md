# 07 · 两条判据的问法（草稿 · 未随实现发布）

> 这一节放**问法与形状**；两条判据的**参考脚本已随仓**（`tools/check-pointer-continuity.mjs` · `tools/check-compaction-accounting.mjs`，各带一份最小样例日志）。
> ⚠️ **随仓 ≠ 已可移植**：它们至今只在**同一个生产者**的日志上撞过（票数 0，见 §6）——拿它量你自己那套之前，先读 §6，并且**先把词形换掉**（§5）。

## 1. 它们各问什么

**A · 接续指针**（「丢状态」那一格）

> 缝（换窗口 / 重启 / 压缩）之后，**眼前的输入里**说不说得出：①上次做到哪 ②在等什么 ③为什么是这个下一步？

**B · 压缩记账**（「上下文爆」那一格）

> 压完之后，**知不知道丢了什么、能不能取回**？

第二问不是我们想出来的，是**逐字借一份外部 survey 自认的空档**（RUC-NLPIR / `Awesome-Long-Horizon-Agents`）：

> *no suite measures compaction the way the formalism requires … whether a scheme knows what it dropped, whether it can get it back*

两条问的都只是**看得见 / 记得起**，**不量做对了**——那半边见 §6。

## 2. 三态与退出码（两条一致）

| 码 | 态 | 含义 |
|---|---|---|
| 0 | ✅ | 满足（A：2–3/3 件可见；B：有账**且**有可取回的落点） |
| 3 | ⚠️ | 半（A：只见 1 件；B：有账但只报数、取不回） |
| 1 | ❌ | 不满足（A：0 件；B：压了但**没有任何账**） |
| 4 | ⚪ | **判不了 / 不适用 —— 不算通过**（A：缺时间戳；B：记录里没有压缩边界） |

⚠️ **⚪ 必须单独计数**。把「不适用」折进「通过」是这类判据最常见的自欺：**一条不跑起来也算绿的判据，等于没有判据**。

## 3. 两条**取法相反**（有意的，别当 bug）

- **A 取最好的一条**：问的是「缝上**有没有**东西」——一条缝上只要有一条说得出，接续就有了。
- **B 取最差的一条**：问的是「**有没有任何一次**压缩是没账的」——一次净损失就是一个洞。

⇒ 同一批记录上，两条判据的总判决可以完全不同；**别把它们的总判决当同一个量来比**。

## 4. 对照要求：负对照必须开在**它自己那一层**

判据的刀口在哪一层，对照就必须在哪一层开火——**判分层的对照证明不了选择没错**。

- **A 的刀口在选择**（哪几条算「缝后的一轮」）⇒ 必须有一条**选择层负对照**：
  *缝后第一轮干净、载体在第二轮 ⇒ 必须 ❌*。
- **B 的刀口在时序**（账必须出现在边界**之后**）⇒ 必须有一条：
  *同形文字出现在边界**之前** ⇒ 不算这次的账*。
- 两条都要另配**时间戳形状**的对照：**epoch 毫秒与 ISO 都要认**。
  （这一条是实测打脸之后补的：只写 ISO 的对照抓不到「尺子不认自己数据格式」——9 个边界曾被全判成 ⚪。）
- 现阶段的对照条数（参考实现）：**A 10/10**（该亮 4 / 该灭 4 / 半与判不了 2）· **B 6/6**。

## 5. 输入契约

```
{"time": <ISO 字符串 或 epoch 毫秒>, "who": "<产者名>", "text": "<正文>"}    # JSONL，一行一条
```

- 你只需要写一个**适配器**：把你那边的日志变成上面这种记录。**判据本身不用改。**
- **词形是契约，不是常量**：边界 / 账 / 落点 / 「上次做到哪」这些话，**每个生产者写法都不同**。
  参考实现把它们全部收进一张表，可由 `--patterns <file.json>` 覆盖。
  **默认值 = 我们那套写法，不是通用真理**；拿去量别人的日志之前先换。
- 验收（我们自己定的一条）：**换成一整套陌生的词形之后，同一条判据仍要跑得动**，并且
  「**同一条记录在默认词形下 ❌、换上那套词形后 ✅**」这个**判别对**要能复现。

## 6. 现阶段的边界（必须连着读）

1. **票数 0**。这两条判据目前只在**同一个生产者**的两条线上撞过（其中一条是它自己的第二条线）⇒ 按我们自己的规矩
   「撞过**三个独立生产者**再决定要不要长成库」，**还不够**。
   ⇒ 我们仍然把它们放出来（`tools/`，各带一份最小样例日志与自带对照），但**不宣称它们可移植**：
   **默认词形是我们那套写法，换掉它才是你该做的第一步**（§5）——不换就会拿到一堆假的 ❌/⚪。
2. **只量「看得见 / 记得起」，不量「做对了」**：A 的 ✅ 不说明接续**有用**；B 的「有落点」不说明**取得回**。
   那半边要另一套装置（零历史探针 + 外部评分器）。
3. **滞后是读数，不是缺陷**：B 的实测里，账最晚 **725 秒**后才到（落在下一次重启那一刻）⇒ 判据把滞后**报出来**，
   而不是拿一个时间窗把它滤掉——滤掉会把「来晚了」误判成「没有」，这是我们踩过的坑。
4. **不换词形就会误判**：使用者若不换掉默认词形，A 会把不认识的说法一律读成 ❌/⚪。**这不是判据的结论，是没接对。**
