# 接续指针（pointer）

> 本模块是 `loopfloor` 主题的一节，按仓骨架的五节模板写：解决什么问题 / 形状 · 协议 / 不在本模块 / 依赖 · 前置 / 状态。

## 1. 解决什么问题

**一句话**：回答「上一段工作停在哪、下一段从哪接」——而且**整个工作线同一时刻只有一个答案**。

**失败场景**：一次上下文压缩或一次进程换代之后，新开的那一轮里没有「上次到哪了」。于是只有两条路：从零重来（把做过的事再做一遍），或照着一份**已经过期**的计划继续做（它看起来还在，但世界已经变了）。

这一类故障**不报错**：会话能正常恢复、上下文看着是完整的、模型也能接着说话——少的只是那一格信息。

## 2. 形状 · 协议

五条约定，都跟「少而准」有关：

1. **单数**：一条工作线同一时刻只有一个当前指针。多份并存时，「哪个才算当前的」本身会变成一件需要判断的事——而判断需要的那格信息，恰恰就是你想要的。
2. **覆盖式**：写入即替换，不追加。历史交给别的东西（变更记录、账本）负责；指针只负责**现在**。
3. **标 source**：每条指针记下它**从哪来**（谁写的、被什么触发）。否则读者无法判断它是否已经过期。
4. **等待态可表达**：形状里要有「在等什么、等谁」。一个只会说「下一步做什么」的形状，会在等待时逼人二选一——**写一个假动作，或把信息清空**。凡是逼使用者迁就的形状，问题在形状。
5. **收口条件必须点名外部物**：这条最硬，见 §3。

**自查判据（读者用）**：换一次窗口之后，**第一轮的输入里有没有「上次到哪了」**？有 = 形状达成；没有 = 等于没接上。

## 3. 不在本模块

- **判据分家**（本模块最重要的一条留白）：
  - **触发条件可以自产**——「什么时候该记一笔」属于本模块；
  - **判据不能自产**——「这一步真成了吗」必须由**本系统之外的东西**回答（一条命令的退出码、一份别人能打开的文件、一条外部读数）。
  - ⇒ **本仓只给形状与约定；判据集不在本仓。**
- 实现代码、存储格式、字段命名不在。
- 调度与规划逻辑不在（指针记录「到哪了」，不决定「去哪」）。
- 任何阈值、路径、凭据不在。

## 4. 依赖 · 前置

- **一个持久落点**：指针必须活过换代。只存在内存里的指针等于没有指针。
- **一个读入口**：每个回合开始前能被读到。**注入型**（每轮自动出现在视野里）比调用型可靠——调用型要靠「记得去读」，而记得这件事本身就是失败模式之一。
- **一个收口动作**：做完的指针要能被覆盖或清掉。只写不清的指针会退化成噪声，而噪声会让人不再读它。
- **一处历史**（可选但推荐）：指针是覆盖式的，所以「做过什么」需要一个别的地方承载；两者分工写清楚，否则会互相污染。

## 5. 状态

- **协议描述**：本文件（骨架）。
- **实现**：我们这边有一份在跑的，形状与 §2 的五条一致；**本批不搬实现代码**，待整理后另放。
- **已知反例**（进正文，不进附录）：① 指针里只有「下一步做什么」时，等待会逼出假动作；② 指针不标 source 时，过期指针会被当成当前的执行；③ 只写不清，指针列表退化成一个没人读的档案。
