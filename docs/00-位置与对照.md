## 2. survey 怎么切这张地图（逐字）

> **L94**：`Long-horizon agency is a system-level capability jointly shaped by external harness engineering and internal model optimization.`

> **L98**（它那张表的左栏 = Externalized Harness Engineering）：
> `Loops and workflows · Context and memory · Tools and skills · Orchestration · Hooks · Verification`

> **L161**：`We formalize a long-horizon agent as a base policy coupled to a surrounding harness,` **Agent = π_θ ⊕ H**`, and organize long-horizon difficulty into` **three nested levels (H1 ⊂ H2 ⊂ H3)**`, each paired with the capability it demands (C1 ⊂ C2 ⊂ C3)`

> **L169**：METR 的 horizon 口径——`the length of tasks an agent can complete at a fixed success rate (e.g., the 50%-task-completion time horizon)`，并明确它把 long-horizon agency 与 `long-running execution, autonomy, and self-evolution` 分开。

⇒ **两条直接后果**：① 「harness engineering」在概念层**已被命名并分类**（六节）；② 它给了「horizon」一个**外部可核的口径**（METR 那种）。

## 3. AMAP 那一份说了什么（逐字）

> **L75**：`### One loop. Three focused responsibilities.`

> **L81**（Manager）：`Rebuilds each round from the original goal, verified progress, failure evidence, and remaining work`

> **L83**（Auditor）：`Independently inspects the actual files, interfaces, logs, and tests instead of trusting the Executor's claim`

> **L140**：`### Same model. Same execution backend. Only the harness changes.`

> **L291（这条改了我们此前的判断，逐字）**：`The adapter runs` **`dsh --profile headless`**`, gives every run an isolated` **`DSH_HOME`**`, uses` **`workspace-write`** `for executors, and uses` **`read-only`** `for the Manager and auditors. … DeepSeek Harness is still a developer preview; this phase intentionally does not expose its Web UI, computer-use plugins, MCP config, or --mcp-add-dir.`

> **L381**：角色超时后 `keeps the partial trajectory and recorded task state, then lets the next Manager round inspect the real workspace and recover`。

⇒ **三条读法**：
1. **它站在 dsh 之上**（不是另一个独立 harness）——所以它和我们**不是竞争者，是上下游**。
2. 它把「状态与下一步」交给一个**角色**（Manager「每轮从原始目标+已验证进度+失败证据重建」），而我们把这件事交给**盘上的东西**（指针 / 目标 / 计划）。**同一个问题的两种解法。**
3. 它有**真验收**（L140 那句就是它 benchmark 的立论方式：同模型、同执行后端、只换 harness）。这一点我们要学：**外部评分器**，不是自评。

## 4. 对照：六格 × 我们四格

| survey 的 harness 六节 | 我们的对应物 | 我们的位置 |
|---|---|---|
| Loops and workflows | ——（刻意不做：零角色、零编排） | 主动放弃 |
| **Context and memory** | 上下文爆：压缩 + 注入面按**变更频率**分层 + 大输出落盘 | **硬**（有读数、有口径） |
| Tools and skills | 工具装载/懒装载/工具面计量 | 有料，未系统化 |
| Orchestration | ——（我们走的是**反方向**：不加角色） | 主动放弃 |
| Hooks and middleware | 插件面（这台 harness 本身就是插件系统） | 有料，属实现层 |
| **Verification** | 假完成：判据 / 失败信号 / 审计三件 / 错误库 | **硬**（我们最不缺失败样本） |
| **（六节里没有这一格）** | **丢状态：接续指针 + 任务态外部化（工作台）** | **空档** |

**这一格空档是这份对照最有用的一条**：六节覆盖了「循环、上下文、工具、编排、钩子、验收」，而**「任务态怎么活过窗口切换 / 压缩 / 进程换代」没有自己的位置**——它被默认塞在 Loop 或 Context 里，但这两个都不是为它设计的。

## 5. 位置（从上面长出来的，不是自评）

> 我们不占「长程 agent 框架」那一格（Loop / Orchestration 两节已有很响的仓）。我们占的是：
> **任务态活过窗口切换与进程换代**——survey 六节里唯一没有自己位置的一格；而它的入口是
> **静默失败学 + 承重判据**（不是再写一个 loop）。

**为什么这个位置立得住**：① 它是**空档**（外部文献的结构里没有它）；② 我们有**实物**（指针 / 工作台 / 压缩三层件 + 错误库 + 失败记录）；③ 它**不怕被"说完"**——说「长程任务要治丢状态」很容易，给出**能复算的判据与失败样本**很难。

## 6. 缺什么（诚实清单）

- **没有外部评分器**：AMAP 有「同模型同后端只换 harness」的对照与 benchmark；我们**没有**。⇒ 对外材料里**不承诺 benchmark**。
- **可回放那条还是论证**（不是实测）：要写就补一个能跑的重放演示，否则在文里标明。
- **第四格的仪表**：**已由专门窗口在做**（2026-09-25 更新，不重复开线）。
- **六节里的 Tools / Hooks 我们没有系统化**：有零散装置，没有成篇的口径。
- ⚠️ **本文件所有「我们」的读数都来自单一部署的会话日志**：样本与口径要随件给出，不能只给百分比。
