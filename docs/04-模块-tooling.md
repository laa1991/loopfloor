# 工具面（tooling）

> 本模块是 `loopfloor` 主题的一节，按仓骨架的五节模板写：解决什么问题 / 形状 · 协议 / 不在本模块 / 依赖 · 前置 / 状态。

## 1. 解决什么问题

**一句话**：工具面**会自己长大**，而它长大时没有任何东西会报警——每一次请求都成功，只是越来越贵、越来越钝。

**失败场景**：工具表悄悄翻倍。每个工具的描述、参数、枚举都被塞进**每一次**请求里；成本随之上升，而**账面上看不出来**——没有报错、没有告警、没有任何一条日志会因为「这次请求多带了两万字符」而变红。等到有人去量，往往已经过去很久。

## 2. 形状 · 协议

六条约定：

1. **先量，再动**：任何一刀之前先有前后读数。**没有口径的瘦身就是凭感觉删**，而凭感觉删的代价是悄悄少掉某项能力，且没人会立刻发现。
2. **按「调用频率 × 单次代价」分层**：
   - **常驻层**：最小必要集，每轮都在；
   - **按需层**：用到才展开；
   - **调用层**：调用那一刻才装。
   分层的依据是**使用分布**，不是工具的「重要性」——大多数工具是偶尔用一次，而它们全都常驻。
3. **名字常驻、schema 按需**：名字很便宜，schema 很贵。让读者知道「有这个东西」，与把它的完整说明塞给他，是两笔完全不同的开销。
4. **先看这个区在请求里的位置**：序化在**历史之后**的区，改动只算尾巴的价钱；序化在**历史之前**的区，改一个字节就是**其后全部历史**的价钱。同一个「瘦身」动作，放在哪一区，收益差一个数量级。
5. **计量对象要选对**：量「工具面占请求的多少」有用；量「某个工具被调用几次」在评价**成本**时常常没用——那测的是使用者的习惯。评价一个**常驻型**的东西，不能用它「被打开几次」。
6. **每一刀都要能说清代价**：删掉之后，谁少了什么能力、什么情况下会疼。**答不出来就先别删**。

**自查判据（读者用）**：工具面占这次请求的百分之几？**上一刀省了多少，你是量的还是猜的？**

### 2.5 最小契约（照着这个能实现你自己那一版）

**A. 必须能回答的六问**

1. **工具面占这次请求的百分之几**（有数，不是感觉）
2. **上一刀省了多少** —— 是**量的**还是**猜的**
3. **分层依据是什么** —— 使用分布，还是「重要性」
4. **每层各放了什么**（名字常驻 / schema 按需 / 调用那一刻才装）
5. **这个区在请求里的位置** —— 序化在历史**之前**还是**之后**
6. **删掉之后谁少了什么能力、什么情况下会疼**

**B. 负对照**

| 缺哪问 | 你会看到什么 |
|---|---|
| 1 | 成本上升而**账面上看不出来**：没有报错、没有告警 |
| 2 | 瘦身变成凭感觉删；代价是悄悄少掉能力，且**没人会立刻发现** |
| 3 | 常驻层会按「重要性」长回去——每个工具的作者都觉得自己的重要 |
| 5 | 同一个瘦身动作放错区，收益差一个数量级 |
| 6 | 删了，但没人知道丢了什么；下一次是同一个错误再犯一遍 |

**C. 最小验收**

量**前后**两个数（工具面占请求的比例，同一条命令取），再**真用一次**那个被改动的能力。
**只报「省了」不报口径，等于没报。**

## 3. 不在本模块

- **具体工具清单与阈值**：本仓**不列**我们在跑哪些工具，也不给「多少把算多」这类阈值——它取决于部署规模与任务类型。
- 注册协议与加载器的实现代码不在。
- 具体的前后瘦身数值：**有实测**，但随读数节给口径；本模块只给方法。
- **判据集不在**（与 `pointer`、`task-surface` 同一条留白）。

## 4. 依赖 · 前置

- **一把能量工具面的尺**（否则瘦身等于凭感觉删）。
- **一个可回滚的注册面**：注册的东西要能卸掉。卸不掉的注册会在热更新或重载时留下幽灵——它们照样占位置，却没人认为自己还拥有它们。
- **一份「谁在用哪个工具」的账**（至少是调用计数）：否则删完不知道伤了谁。**账要能区分「没人用」与「没人量到」**——这两件事在计数上长得一样。
- **一处能跑正对照的地方**：删之前留一条「它会用上」的实例，删之后用来验证代价。

## 5. 状态

- **协议描述**：本文件（骨架）。
- **实现**：我们这边有实现，也有前后读数（工具面在请求里是**个位数量级**的占比）；**本批不搬实现代码**。
  ⚠️ **「个位数量级」与 §1 的「会自己长大」不矛盾——两个刻度**：占比是**当前读数**（单会话一帧），§1 说的是**趋势**：它只涨不跌，**涨的时候没有任何东西会响**。⇒ **便宜 ≠ 安全**：危险不在今天的占比，在**无声累积**（一年后没人说得清哪些还该在）。
  ⇒ **什么时候该怕它**：当你答不出 §2.5 任一问的时候——尤其第 2 问（**上一刀省了多少，量的还是猜的**）。
- **已知反例**（进正文，不进附录）：
  1. **第一刀砍空**——最该瘦的那些工具描述本来就很短（零参、无枚举），注释没什么可删的；真正的体积在少数几个大工具身上；
  2. **把调用次数当成本**——一个每轮都出现的常驻面，调用次数可以很低而成本很高；
  3. **删完没有读数**——既不知道省了多少，也不知道伤了谁；下一次就没人愿意再动它；
  4. **只看名字不看位置**——把「工具面很小」当成「它不重要」，于是忽略了「改它破不破前缀」这一层。
